# 2026 年 12 月计划（31 天）：ChainPay-Lab POC

> 周期：2026-12-01（周二）至 2026-12-31（周四）。
> POC 入口：[poc/chainpay-lab](../poc/chainpay-lab/README.md)。
> 月度记录：[practice/2026-12](../practice/2026-12/README.md)。

12 月以 ChainPay-Lab 为唯一主线，交付一个能在本地固定数据上运行、测试和演示的只读对账助手。它读取订单、账本和差错池，调用白名单工具，输出结构化差异报告和建议。语言只按 POC 实现需要选择，不单独安排语法学习或多语言改写任务。

## 月度目标

- 固定订单、账本、差错池和事件样例，定义可重复的输入输出。
- 完成订单查询、账本查询、差错池查询和对账汇总四个只读工具。
- 为 Agent 定义工具白名单、输入输出 schema、超时、重试和拒绝越权操作的边界。
- 覆盖重复事件、乱序事件、单边账、金额不一致、空数据、工具超时和错误输出。
- 记录 run id、工具耗时、失败原因和结构化评估结果，完成一次可复现的本地演示。

## 分周计划

### 第 1 周（12/01–12/06）锁定 POC 范围与数据

确认只读对账助手的用户路径和输出格式。整理 `poc/chainpay-lab/agent-payments/fixtures/` 中的订单、账本、差错池和事件样例，给每条数据补稳定 ID。写一页工具协议，明确每个工具的输入、输出和错误。

当周交付是固定 fixtures、字段说明、成功样例和三类差错样例。运行一次本地读取验证，并把命令追加到 `practice/2026-12/README.md` 的记录区。

### 第 2 周（12/07–12/13）实现只读工具与对账核心

选择 Java 或 Go 作为 POC 主实现，完成四个只读工具和一个对账汇总入口。先让工具读取固定文件或内存数据，再把结果合并为稳定的结构化报告。每个工具都返回明确的成功、空结果和输入错误。

当周交付是 `poc/chainpay-lab/agent-payments/tools/` 下可调用的工具、核心对账函数和一条端到端命令。输出至少包含匹配项、金额差异、单边记录和差错池摘要。

### 第 3 周（12/14–12/20）加入 Agent 边界与异常路径

为 Agent 增加工具白名单、参数校验、超时、有限重试和结构化输出校验。明确所有写操作都被拒绝，外部网络和真实支付系统保持关闭。测试重复执行、乱序输入、重复事件、工具超时、错误 JSON、超长上下文和权限拒绝。

当周交付是评估样例和失败路径测试。每个失败用例记录预期错误、实际错误和恢复方式。

### 第 4 周（12/21–12/27）补齐审计与本地演示

记录 run id、输入摘要、工具调用顺序、工具耗时、输出摘要和失败原因。补一条本地启动入口，优先复用现有 Makefile、Docker Compose 或脚本模板。管理台或命令行只展示只读结果、建议和审批状态，不执行写操作。

当周交付是可重复的演示脚本、日志样例、健康检查和故障排查说明。新环境按照 README 能完成一次从输入到报告的运行。

### 第 5 周（12/28–12/31）验收与下月 backlog

执行全量测试，检查报告中的借贷平衡、重复事件、乱序事件、超时、重试和单边账。整理架构图、工具 schema、运行命令、演示输出和已知限制。把未完成项分为可靠性、观测、数据和产品四类，形成 2027 年 1 月候选清单。
