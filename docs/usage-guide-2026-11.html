项目身份

当前仓库的周期标识是 coding-sprint-lab-2026-11。机器可读的身份信息集中在 project.yml，其中 cycle 表示当前月份，project_id 表示项目与周期的组合，plan 指向本月计划。

先看这三个文件。 project.yml 确认当前周期，monthly-plan-2026-11.md 确认任务，README.md 确认项目入口和迭代命名。

本月目标

建立可复用的多语言工程手感，并交付 ChainPay-Lab Agent 只读对账助手的可运行、可测试、可演示 POC。

默认边界

Agent 默认读取模拟数据，外部副作用关闭。写操作需要明确的审批边界，Solidity 只用于本地或测试网的模拟事件。

仓库结构

顶层目录按职责划分。学习产物、POC、可复制模板和文档分别归档，避免把一次性实验混入长期复用的工程模板。

目录放什么维护方式

docs/计划、架构、决策、运行手册和月度复盘按周期归档，保留已完成月份的原始计划

每日工作流

每天围绕一条小闭环推进。先确认当天目标，再完成代码、测试、记录和提交，确保第二天可以从仓库状态继续。

  1. 确认范围。 打开 月度计划，定位当天的 D 编号、语言主题和 POC 交付物。
  2. 建立目录。 语言练习使用 practice/<language>/day-XX-topic/，LeetCode 使用 practice/leetcode/<language>/day-XX-slug/。
  3. 完成最小实现。 代码放在练习目录，配套 README、测试和必要的 notes，保持入口清晰。
  4. 验证结果。 至少运行一个有意义的测试或验证命令，同时覆盖边界、错误和重复执行路径。
  5. 记录复盘。 写下当天一个决策、一个问题和下一步动作。LeetCode 还要记录题型、复杂度、测试用例和改进点。
  6. 提交变更。 使用 Conventional Commit，提交前运行 git diff --check 并确认 git status 中没有误加入的文件。
时间分配参考。 每天约 2 小时，其中语言训练 50 分钟，POC 40 分钟，Agent 实验或评估 20 分钟，测试、Review 与记录 10 分钟，另安排 30 至 45 分钟完成一题 LeetCode。

文件或目录用途

题目目录建议使用稳定的英文 slug，例如 day-01-two-sum。同一题的多语言版本保持相同的日期和 slug，方便对比实现。

POC 与模板管理

ChainPay-Lab POC

poc/chainpay-lab/ 保存订单、账本、事件和 Agent 只读对账助手的实验。工具 schema、fixtures、评估集和观测资料各自放在对应子目录。

可复用模板

templates/ 保存语言和基础设施的起始骨架。模板应能被新项目复制，避免把本月 POC 的业务细节反向写入通用模板。

Agent 任务的交付要求
  • 声明工具白名单、输入和输出 schema。
  • 记录超时、重试、重复执行和错误输出路径。
  • 默认使用模拟数据，写操作保留人工审批边界。
  • 保留 run id、工具耗时、失败原因和评估结果。

Git 管理

Git 用来记录小步可回溯的学习和工程增量。每次提交围绕一个清晰主题，提交消息遵循 Conventional Commits。

git status
git diff --check
git add practice/leetcode/java/day-01-two-sum
git commit -m "feat(java): add two sum solution"
类型适用场景示例
feat新增练习、工具或 POC 能力feat(go): add expiring cache
docs更新计划、说明和复盘docs(plan): update November checklist
test补充测试和评估样例test(agent): cover timeout path
chore目录、模板和工具维护chore: scaffold leetcode folders

不要把 IDE 配置、密钥、真实资金凭证或未授权的外部写操作混入提交。提交前检查文件路径和差异内容。

月度迭代方法

每个月保留一个独立的计划文件和一个明确的项目标识。这样可以从历史周期回看目标、交付和未完成项，也能避免覆盖上个月的计划。

  1. 复制文档。 将本月计划整理为 docs/monthly-plan-YYYY-MM.md，同步生成 docs/usage-guide-YYYY-MM.html，并保留旧月份文件。
  2. 更新身份。 修改 project.yml 的 cycle、project_id、status、plan 和 guide。
  3. 更新入口。 在 README 和 docs/README.md 增加新月份的链接和目标。
  4. 切换范围。 把上月未完成项转入 backlog，明确本月唯一的 POC 主线和不在范围内的方向。
  5. 建立目录。 需要新的练习语言或 POC 子模块时，先补目录说明和最小模板，再开始写实现。
  6. 月末归档。 完成全量验证和复盘后创建 Git 标签 cycle-YYYY-MM，并把下一月候选项记录到复盘文档。
月份改变时只更新当前周期指针。 历史计划和指南文件保持原名。项目 ID 的固定格式是 coding-sprint-lab-YYYY-MM，计划文件的固定格式是 monthly-plan-YYYY-MM.md，指南文件的固定格式是 usage-guide-YYYY-MM.html。

每日与月末验收

每日验收

  • 代码或配置已放入对应目录
  • 至少一个测试或验证命令通过
  • 记录一个决策、一个问题和下一步
  • LeetCode 题解包含复杂度和复盘
  • 提交消息符合 Conventional Commits

月末验收

  • 主线语言和辅助语言模板可运行
  • POC 在模拟数据上完成闭环
  • Agent 评估覆盖成功、超时、重复和拒绝
  • 本月 LeetCode 记录可复盘
  • 未完成项已转入下月 backlog
