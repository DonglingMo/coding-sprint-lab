# Agent 只读对账助手

本目录只承载当前月的单一 POC 模块：读取固定 mock 的订单、账本和差错池，生成结构化差异摘要与可审计建议。

## Scope

- 允许读取：订单状态、账本分录、链上事件摘要、差错池和评估夹具。
- 允许输出：差异摘要、证据引用、风险标签、建议动作和评估结果。
- 默认只读：不扣款、不退款、不转账、不修改账本、不调用真实 PSP 或链上合约。
- 当前月不展开：Web3 UTA、DEX、传统支付写入链路及其他业务扩展。

## Directory Skeleton

- tools/：只读工具契约与调用边界。
- schemas/：输入、工具结果、差异摘要和评估结果 schema。
- fixtures/：固定订单、账本、事件和差错池 mock 数据。
- policies/：工具白名单、字段脱敏、限额和人工确认规则。
- evals/：成功、重复、乱序、超时、错误输出和越权评测样例。
- observability/：run id、工具耗时、失败原因和评估记录约定。
- demo/：本地演示步骤、输入样例和预期输出。

## 30-Day Task Split

### Phase 1：边界与夹具（D1-D5）

- D1：确定订单、账本、差错池的最小字段和只读边界。
- D2：定义工具白名单、禁止操作和人工确认点。
- D3：定义输入、工具结果、差异摘要和证据引用 schema。
- D4：准备一组正常 mock 数据和一组可控异常数据。
- D5：补充目录 README、命名约定和本地运行说明。

### Phase 2：只读工具契约（D6-D10）

- D6：订单查询工具契约。
- D7：账本查询工具契约。
- D8：差错池查询工具契约。
- D9：事件摘要查询工具契约。
- D10：统一错误、超时和空结果约定。

### Phase 3：对账任务拆分（D11-D16）

- D11：订单与账本金额匹配规则。
- D12：订单与事件状态匹配规则。
- D13：重复、乱序和缺失数据的差异分类。
- D14：生成结构化差异摘要和证据引用。
- D15：建议动作只读化，禁止隐式写操作。
- D16：形成一条可重复运行的 mock 对账流程。

### Phase 4：策略与评估（D17-D22）

- D17：工具白名单、字段脱敏和权限拒绝样例。
- D18：超时、重试、重复执行和上下文过长样例。
- D19：错误输出、提示注入和越权请求样例。
- D20：评估结果格式、评分维度和失败原因。
- D21：记录 run id、工具耗时和评估结果。
- D22：完成最小评估集和一次复盘。

### Phase 5：演示与验收（D23-D30）

- D23-D24：准备本地演示输入、预期输出和故障路径。
- D25-D26：补齐 observability 和恢复说明。
- D27：跑通成功、异常和权限拒绝三条演示路径。
- D28：整理 README、目录说明和运行步骤。
- D29：完成全量评估与 Review。
- D30：记录结论、遗留问题和下月候选模块。

## Acceptance Checklist

- [ ] 所有工具都是只读，且有白名单和拒绝样例。
- [ ] mock 订单、账本、事件和差错池可重复加载。
- [ ] 能输出结构化差异摘要、证据引用和评估结果。
- [ ] 覆盖重复、乱序、缺失、超时、错误输出和越权请求。
- [ ] 每次运行都有 run id、工具调用记录和失败原因。
- [ ] README、演示脚本和下月 backlog 已更新。
